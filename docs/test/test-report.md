# 知识问答子系统测试报告

| 版本 | 日期 | 测试对象 | 测试结论 |
|---|---|---|---|
| v1.0 | 2026-06-07 | 知识问答子系统第 14 周版本 | 通过 |

## 1. 测试概述

本报告记录“海外藏中国文物知识管理与服务平台”知识问答子系统的测试范围、测试环境、测试方法、测试结果和遗留风险。

本次测试覆盖前端问答页面、FastAPI 后端接口、MySQL 数据访问、Neo4j 图谱查询、意图识别、`objectId` 解析、多轮上下文、轻量 RAG 答案生成、用户反馈、后台管理接口和统计接口。

## 2. 测试目标

本次测试重点验证以下目标：

1. `/api/qa/ask` 问答主接口可以按统一格式返回答案、事实内容、补充说明、来源和推荐文物。
2. 11 类简单问答功能能够被正确识别和路由。
3. 基础复杂问答能够通过 Neo4j 和 MySQL 完成统计、关系和城市补充查询。
4. `objectId` 能够在前端、MySQL、Neo4j、日志和反馈中作为统一文物标识。
5. 多候选文物能够返回候选列表并由用户选择。
6. 多轮上下文能够支持“它”“该文物”等代词追问，并保留最近 5 轮上下文。
7. 答案能够区分 `factContent` 和 `supplementalContent`，并提供 `sources` 来源说明。
8. 知识库无数据或问题超出范围时，系统能够明确兜底，不编造事实。
9. 用户反馈、审核任务、后台日志查询和统计接口能够正常工作。
10. 前端项目可以正常构建，后端自动化测试可以通过。

## 9. 缺陷与处理记录

| 编号 | 问题 | 处理结果 |
|---|---|---|
| BUG-001 | 点击候选文物后仍重复弹出候选列表 | 已修复：只有 `need_clarification` 状态展示候选 |
| BUG-002 | 清空 `objectId` 后仍使用旧上下文回答 | 已修复：新会话清空上下文和 URL 参数 |
| BUG-003 | 唯一文物名称识别后仍展示候选列表 | 已修复：唯一命中直接回答 |
| BUG-004 | 图谱回答直接显示 `objectId`，用户不易理解 | 已优化：回答中使用文物标题 |
| BUG-005 | 同名候选文物信息不足，难以区分 | 已优化：候选卡片补充图片、材质、尺寸、馆藏、朝代、类型、详情页 |

当前未发现阻塞第 14 周子系统演示的缺陷。

## 10. 遗留风险与后续建议

| 风险 / 限制 | 影响 | 后续建议 |
|---|---|---|
| 多轮上下文为内存基础版 | 服务重启后上下文丢失 | 后续持久化到 `qa_session` 或 Redis |
| 后台接口尚未接入统一鉴权 | 演示环境可用，正式环境存在权限风险 | 与后台管理子系统集成登录和权限校验 |
| 意图识别以规则为主 | 对复杂自然语言表达的覆盖有限 | 后续引入语义分类模型或 LLM 辅助意图识别 |
| LLM 是可选补充能力 | 第三方接口不稳定时补充说明回退模板 | 增加重试、超时配置和调用监控 |
| 作者生平等字段存在数据缺失 | 对应问题可能返回暂无数据 | 与数据组补充字段或扩充知识图谱 |
| 比较类问答和历史人物路径查询未完整实现 | 复杂问答能力仍是基础版 | 第 16 周或后续阶段增强多跳推理和比较问答 |

## 11. 测试结论

综合自动化测试、前端构建测试和人工联调测试，知识问答子系统当前版本达到第 14 周子系统检查要求：

1. 后端自动化测试 38 个用例全部通过。
2. 前端 Vue 项目可以正常生产构建。
3. 问答主流程、MySQL 查询、Neo4j 查询、答案生成、来源展示、反馈审核和后台统计均可运行。
4. 系统能够覆盖项目要求中的 11 类简单问答，并完成多轮对话、复杂问答基础版和问答质量反馈机制。
5. 系统具备可信问答控制：无事实不编造，事实内容与补充说明分离，答案来源可追踪。

结论：本版本测试通过，可以用于子系统答辩演示，并可作为后续 Web、App 和后台管理系统集成的基础版本。
